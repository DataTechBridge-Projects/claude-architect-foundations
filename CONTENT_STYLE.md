# Content Style Guide — CCA-F Study Guide

This guide governs how lecture content is written across this repo. Every
section is generated by an independent agent working from `data/manifest.json`
alone, so consistency depends on everyone following this file exactly.

## Source of truth

- `data/manifest.json` lists every section (folder, title) and every lecture
  in it (filename, title, duration, `target_words`). Do not invent lectures,
  rename files, or change durations — only fill in content.
- There is no real transcript for these lectures. Content is **synthesized**
  from the lecture title, its position in the curriculum, and general
  knowledge of Claude/Anthropic architecture (agents, tools, MCP, prompting,
  context management). Write it as genuine, accurate, well-reasoned study
  content — not as a guess or a summary of "what this lecture might cover."

## File format

Every lecture file already exists as a stub with YAML front matter filled in
(title, parent, nav_order, duration) and a `<!-- CONTENT-PLACEHOLDER -->`
comment. **Do not touch the front matter or the `# Title` heading.** Replace
only the placeholder comment with real content, keeping everything above it
intact.

## Writing style: full narrative notes

Write like a well-organized textbook chapter or expert explainer, not a
bullet-dump. Prose paragraphs carrying the explanation, with structure
(`##`/`###` headings, occasional bullet or numbered lists, tables where
genuinely useful) used to organize — not replace — the narrative. Favor:

- Concrete explanations over vague generalities. If the topic is "Structured
  Tool Use," explain *what* structured tool use is, *why* it matters
  architecturally, and *how* it shows up in Claude Code / the Claude API,
  with a concrete example.
- Definitions of key terms inline, in bold, the first time they appear.
- A short **"Why it matters for the exam"** callout (2-4 sentences) near the
  end of substantive lectures (skip it for very short asides).
- Consistent terminology with the rest of the course: this is CCA-F, whose
  five domains map to five "layers" — Agentic, Tool, Workflow, Prompt,
  Context (plus Fundamentals/orientation content). Use that vocabulary.

## Length targets

`target_words` in the manifest is a target, not a hard cap — treat it as
"roughly this much," within about ±20%.

- `target_words: null` means the lecture has no runtime (quiz prep, role
  play, the practice exam, or a reference-only lecture) — see **Special
  lecture types** below for what to write instead.
- Every lecture, including short sub-1-minute "aside" lectures, targets
  **300+ words minimum**, even where the original video ran well under a
  minute. Expand with genuine substance — a worked example, a second
  paragraph of concrete detail, a connection to another lecture — never with
  padding, throat-clearing, or restating the same sentence three ways.
- Long entries (15+ minutes) are full chapters: use subheadings to break them
  up, and don't be afraid of real depth.

## Special lecture types (no duration / no `target_words`)

- **`Quiz Prep: The X Layer (20 Questions)`** — Write an actual 20-question
  practice quiz covering that layer's module. Multiple choice (4 options,
  A–D), one correct answer. Put the answer key with a one-line rationale
  per question in a `## Answer Key` section at the end (don't interleave
  answers with questions — that lets the file double as a timed drill).
- **`Full Sample Exam (60 Questions)`** — Same format, scaled up to 60
  questions spanning all five layers plus fundamentals, roughly proportional
  to how much of the course each layer occupies. This is the single most
  important file in the repo — take real care with it. Vary question style
  (straight recall, "which of the following is NOT," scenario-based
  judgment calls) the way a real certification exam would.
- **`Role Play: Mentoring on X Essentials`** — Write a short (400-700 word)
  dialogue or scenario in which a mentor walks a mentee through applying that
  module's concepts to a concrete situation. Should reinforce the module's
  key distinctions, not introduce new material.
- **`CCA-F Official Webpage` / similar reference-only lectures** — Keep this
  brief (~100-150 words): note what this lecture points to and remind the
  reader to check Anthropic's official CCA-F page for the authoritative,
  up-to-date exam blueprint, since this repo is unofficial self-authored
  prep material.

## Section index pages

Each section folder has an `index.md` with a
`<!-- SECTION-OVERVIEW: ... -->` placeholder. Replace it with a 2-4 sentence
overview of what the module covers and why it matters for the exam. Leave
the lecture table below it untouched.

## Tone

Confident, precise, exam-focused. Second person is fine ("you'll see this
tested as..."). No filler like "In this lecture, we will discuss..." — just
teach the material.
