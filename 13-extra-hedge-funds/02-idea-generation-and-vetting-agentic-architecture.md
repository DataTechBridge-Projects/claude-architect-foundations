# Idea Generation/Vetting - Agentic Architecture
{: .no_toc }

*Video duration: 8:27*

The single most consequential architectural decision in an idea generation and vetting system is whether generation and vetting should be the *same* agent or *different* agents. It's tempting to build one capable agent that reads the inputs, drafts a thesis, and then critiques its own work in a follow-up turn — it's simpler to build and it's cheaper to run. It is also, for this use case, the wrong default. An agent that just spent several turns building enthusiasm for a thesis carries that enthusiasm into its own critique. This is the same failure mode the Prompt layer's material on quality enforcement calls "grading your own homework": a single context thread that both generates and evaluates tends to rediscover its own conclusions rather than genuinely stress-test them. The fix is architectural, not just a matter of prompting harder — give generation and vetting to separate agents with separate context windows, so the vetting agent approaches the thesis the way a skeptical outside reader would, with no memory of *why* the idea seemed appealing in the first place.

## A Multi-Agent, Not Single-Agent, Design

The system is best built as a small multi-agent pipeline with a coordinator and two to three specialized subagents, rather than either a single monolithic agent or a large swarm. A **screening agent** scans incoming filings, transcripts, and news for candidate patterns and produces a short list of "worth investigating" flags — this stage benefits from breadth over depth, so it's tuned to be generous and cheap to run per item. A **generation agent** takes a flagged candidate and does the deeper work of building a structured thesis: the core claim, the catalysts, the time horizon, and the conditions under which the thesis would be wrong. A **vetting agent**, instantiated fresh with no access to the generation agent's reasoning trace (only its final output), is tasked explicitly with attacking the thesis — searching for contradicting evidence, checking it against the fund's risk-factor taxonomy, and checking it against the fund's own history of similar ideas. A lightweight coordinator sequences these stages and assembles the final packaged output.

This is a pipeline-of-specialists pattern, not a peer-negotiation pattern — each subagent has one clearly bounded job, and control flows in one direction (screen, then generate, then vet) rather than agents debating back and forth. That's a deliberate choice: back-and-forth negotiation between agents adds coordination overhead and non-determinism that this task doesn't need, since the actual value comes from the *separation of cognitive posture* between generating and vetting, not from open-ended dialogue. It's worth naming the alternative and why it loses: a single-agent design with a "self-critique" prompt is cheaper and simpler, and might be acceptable for a low-stakes internal brainstorming tool. But given that a plausible-sounding fabricated thesis can consume real analyst time or, worse, survive into a portfolio decision, the marginal cost of a second agent invocation is worth paying for the independence it buys.

## Autonomy Boundaries

Every agent in this pipeline has narrow, explicit autonomy, and none of them has autonomy over anything except *producing information for a human to evaluate*. The screening agent decides which candidates are worth passing along — a low-stakes decision, since the cost of a bad pass-along is a few minutes of downstream compute, not capital risk. The generation agent decides how to frame a thesis and which evidence to foreground — a higher-stakes decision, but still bounded, because its output is explicitly labeled as a draft and never reaches a portfolio manager unmediated. The vetting agent has the most consequential autonomy of the three: it decides what counts as meaningfully contradicting evidence and how severe a risk-factor conflict is. Because that judgment materially shapes whether a human takes an idea seriously, the vetting agent's output is structured (a risk severity rating, a list of citations, an explicit "confidence" statement) rather than free-form prose, so a reviewing analyst can quickly see the basis for the vetting agent's conclusions rather than having to fully re-derive them.

None of the three agents has any tool that touches execution, position sizing, or anything resembling capital allocation — those tools simply don't exist in this system's toolset, which is the cleanest possible autonomy boundary because it can't be bypassed by a clever prompt or an edge case in reasoning. The agents can read filings, query market data, search past thesis archives, and query the risk-factor taxonomy; none of them can write to a portfolio, submit an order, or communicate directly with anyone outside the research desk's own review queue. This mirrors a principle worth stating explicitly: the safest autonomy boundary is usually "the tool doesn't exist," not "the model has been instructed not to use it."

## What Requires Human Sign-Off

Every thesis that reaches this system's final output is a draft, full stop — no thesis is ever surfaced to a portfolio manager, sized into a paper or live position, or logged as an actionable idea without an analyst reviewing the packaged output first. That review isn't a rubber stamp on principle: the packaged output is deliberately structured to make the review fast rather than perfunctory, with the thesis, its supporting evidence, its contradicting evidence, its risk-factor flags, and its source citations all laid out so an analyst can spend their attention on judgment rather than on reconstructing what the system did. The analyst's sign-off is where the fund's actual investment judgment — mandate fit, conviction, position sizing, timing — enters the process, none of which the system attempts to model.

A second, less obvious sign-off point sits inside the pipeline itself: when the vetting agent flags a *severe* risk-factor conflict (for instance, a thesis that would meaningfully increase the fund's exposure to a factor it's already overweight, or an idea that closely resembles a thesis that lost money for the fund before), that flag should route the item to a senior analyst for review before it's even packaged as a "clean" candidate, rather than being buried as one line among several in the final output. This two-tier review — routine analyst review for every idea, escalated senior review for flagged conflicts — keeps the system's autonomy calibrated to the actual stakes of what it's producing, rather than treating every output as equally reviewable in the same five minutes.

## Architecture Notes

The generator/vetter split is the Agentic layer's answer to a Workflow-layer problem: rather than relying on a single prompt to enforce quality through self-critique, the system enforces it structurally by giving each cognitive posture its own agent and its own context. Autonomy is scoped tightly here — every agent can read and reason, none can act on capital — which is the Agentic layer's core lesson that autonomy should be granted per-capability, not per-agent, and that the safest boundary is a tool that was never built rather than an instruction that could be ignored.
