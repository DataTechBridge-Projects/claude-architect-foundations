# Quiz Prep: The Workflow Layer (20 Questions)

Twenty scenario and recall questions covering `CLAUDE.md`, Skills, workflow sequencing, and CI/CD integration. Choose the single best answer for each, then check your work against the Answer Key at the end.

1. What is the defining property of a `CLAUDE.md` file that most distinguishes it from a normal prompt?
   A. It is written in a stricter syntax than a prompt
   B. It is automatically loaded into every session in that project without being re-supplied
   C. It can only contain build and test commands
   D. It is generated by Claude itself at the start of each session

2. A team wants Claude to always know that database migrations are one-way and must never be edited after being applied. Where should this go?
   A. A Skill triggered only when migrations are discussed
   B. A `CLAUDE.md` entry, since it's a stable, always-relevant constraint
   C. A subagent dedicated to migrations
   D. A RAG index of past migrations

3. Which of the following is the strongest anti-pattern for `CLAUDE.md` content?
   A. Documenting the command to run the test suite
   B. Pasting the team's entire architecture decision record and incident history into it
   C. Noting that database access must go through the repository layer
   D. Defining project-specific vocabulary

4. How does a `CLAUDE.md` file most fundamentally differ from a system prompt?
   A. `CLAUDE.md` is project-scoped and owned by the team working in that repo; a system prompt is harness-level and usually spans many projects
   B. A system prompt cannot contain constraints, only `CLAUDE.md` can
   C. `CLAUDE.md` is only visible to the model, never to humans
   D. System prompts are version-controlled; `CLAUDE.md` files are not

5. A piece of knowledge is large, changes weekly, and is only relevant to a small fraction of queries. What's the best home for it?
   A. A `CLAUDE.md` entry
   B. A system prompt addition
   C. Retrieval (RAG), fetched only when a query actually needs it
   D. A Skill trigger description

6. What best describes a Skill, architecturally?
   A. A separate agent with its own context window
   B. A packaged, invokable procedure — instructions and sometimes bundled tools — loaded on demand into the current agent's context
   C. A permanent addition to the system prompt
   D. A CI/CD pipeline stage that always runs on every commit

7. What mechanism allows an agent to know a relevant Skill exists without loading every Skill's full content into context on every turn?
   A. Progressive disclosure via a lightweight index of names and trigger descriptions
   B. Random sampling of available Skills
   C. A separate model call dedicated to Skill selection
   D. Skills are always fully loaded; there is no discovery step

8. A Skill's trigger description is too vague ("helps with documents"). What's the practical consequence?
   A. None — trigger descriptions don't affect behavior
   B. The agent may fail to invoke it when relevant, or invoke it for unrelated tasks that superficially match
   C. The Skill will automatically be merged into `CLAUDE.md`
   D. It will cause a CI/CD pipeline failure

9. A task requires isolated reasoning in its own context window, with its own independent model call, separate from the calling agent's ongoing context. What's the right mechanism?
   A. A Skill
   B. A `CLAUDE.md` entry
   C. A subagent
   D. A deterministic CI step

10. Which statement correctly distinguishes a subagent from a Skill?
    A. A subagent loads instructions into the current context; a Skill spins up a new context window
    B. A subagent gets its own context window and makes independent model calls; a Skill's content is loaded into the current agent's existing context and the same agent continues acting
    C. They are functionally identical mechanisms with different names
    D. Skills can only be used in CI/CD; subagents can only be used interactively

11. A workflow step computes a SHA-256 checksum of a file. How should this step be built?
    A. As an agentic step, since correctness matters
    B. As a deterministic step — the correct output is fully specified by the input, with no judgment involved
    C. As a Skill that a human must manually trigger
    D. As a multi-agent step for redundancy

12. A step involves an intricate but fully-specified tax calculation with many branches. What's the correct classification?
    A. Agentic, because it's complex
    B. Deterministic — complexity alone doesn't imply the need for judgment if the logic is fully specifiable in advance
    C. It must be split across two subagents
    D. It should be handled entirely by a human, never automated

13. What is the practical benefit of the "deterministic steps bound and validate agentic steps" pattern?
    A. It eliminates the need for any human review
    B. It narrows what the agentic step reasons over and catches constraint violations before they propagate, combining agentic flexibility with deterministic safety
    C. It guarantees zero latency
    D. It removes the need for CI/CD integration entirely

14. A workflow's step order genuinely can't be determined in advance — the right next step depends on what was just discovered. What does this suggest?
    A. The workflow should be a fixed pipeline with steps in a hardcoded order
    B. The sequencing itself likely needs agentic control, favoring a single autonomous agent (or multi-agent system) over a fixed pipeline
    C. This is a sign the task should be abandoned
    D. All steps should be converted into `CLAUDE.md` entries

15. Why is a fixed pipeline often preferable to a single freely-reasoning agent when the step sequence is fully predictable in advance?
    A. Fixed pipelines are always more accurate
    B. Fixed pipelines are cheaper, faster, and easier to audit because control flow is visible in the definition rather than implicit in model decisions
    C. Agents cannot execute deterministic steps at all
    D. Fixed pipelines don't require any testing

16. A developer occasionally pastes a diff into a chat and asks Claude to review it before merging. What is this missing to be considered CI/CD-integrated?
    A. Nothing — this already counts as CI/CD integration
    B. A defined trigger, reproducible input, durable captured output, and explicit gating behavior tied to the pipeline
    C. A larger context window
    D. A dedicated subagent for every review

17. In a CI/CD pipeline, a Claude-generated documentation change is drafted for a compliance-relevant page. What gating approach best fits the stakes involved?
    A. Auto-merge immediately with no checks
    B. No gate at all — trust the model's output
    C. A hard gate: mandatory human sign-off and/or deterministic validation (e.g., link checker, schema validator) before it proceeds
    D. Delete the step entirely since documentation doesn't matter

18. Which of these is NOT one of the properties needed to make a Claude-driven CI step legitimately "auditable and automated"?
    A. A defined trigger
    B. Captured, durable output
    C. Logging of the interaction, not just the final result
    D. Running the step manually whenever someone remembers to

19. Why should a Claude-driven CI step have logging, retries, and a rollback/fallback path just like any other pipeline step?
    A. Because agentic steps are inherently more reliable and need less oversight
    B. Because exempting it from normal operational discipline is exactly what makes it the least reliable part of the system
    C. Because retries are required by law for AI-generated content
    D. Because logging replaces the need for gating

20. A team debates whether a particular workflow convention (e.g., how detailed their PR review checklist should be) needs to become an org-wide standard. What does this module suggest?
    A. All workflow conventions must always be centralized for consistency
    B. Many workflow conventions are legitimately local to one team or repo, and forcing them into a single global standard often produces a worse fit for everyone
    C. Local conventions are never acceptable in production systems
    D. Only CI/CD administrators may define workflow conventions

## Answer Key

1. **B** — `CLAUDE.md`'s defining property is automatic, persistent loading without being re-supplied each time.
2. **B** — A stable, always-relevant hard constraint belongs in `CLAUDE.md`, not a task-specific or on-demand mechanism.
3. **B** — Dumping large archival material into `CLAUDE.md` bloats context paid on every session; it should stay tight and durable.
4. **A** — `CLAUDE.md` is project-scoped and team-owned; system prompts are harness-level and cross-project.
5. **C** — Large, volatile, query-specific knowledge is the textbook case for retrieval rather than standing context.
6. **B** — A Skill packages instructions (and optionally tools) and is loaded on demand into the current agent's context.
7. **A** — Progressive disclosure: a lightweight index is always visible; full Skill content loads only when triggered.
8. **B** — A vague trigger description is the only signal evaluated every turn, so vagueness causes missed or spurious invocations.
9. **C** — Isolated context and independent model calls are exactly what a subagent provides and a Skill does not.
10. **B** — This is the core mechanical distinction: separate context/model calls (subagent) vs. same-context augmentation (Skill).
11. **B** — A checksum has one fully-input-specified correct answer; no judgment is needed, so it should be deterministic.
12. **B** — Many branches is complexity, not ambiguity; fully-specifiable logic is deterministic regardless of how intricate it is.
13. **B** — Deterministic pre/post steps narrow and validate agentic output, combining flexibility with safety.
14. **B** — Unpredictable step ordering is a signal that sequencing itself needs agentic judgment, not a fixed pipeline.
15. **B** — Predictable sequences don't need runtime judgment to determine order, so a fixed pipeline is cheaper and more auditable.
16. **B** — Ad hoc usage lacks a pipeline trigger, reproducible input, durable output, and defined gating — the four pillars of integration.
17. **C** — High-stakes, hard-to-reverse output warrants a hard gate combining human review and/or deterministic validation.
18. **D** — Running manually "when someone remembers" is the definition of ad hoc, the opposite of automated and auditable.
19. **B** — Exempting agentic steps from normal operational rigor is precisely what makes them fragile and unreliable in production.
20. **B** — The module explicitly argues many workflow conventions are legitimately local and shouldn't be force-fit into a global standard.
